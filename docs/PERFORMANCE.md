# VPN performance guide

How to improve connection speed and internet throughput in the two-hop WireGuard stack.

See also: [ARCHITECTURE.md](ARCHITECTURE.md) for traffic paths.

---

## Quick start (operators)

On **each** server (entry and exit):

```bash
sudo bash deploy/tune-vpn-performance.sh
```

This runs routing repair, enables TCP MSS clamp, applies BBR + UDP buffer sysctl, syncs VPN modes on entry, and prints diagnostics.

Verify from a **connected client device**:

```bash
curl -4 https://api.ipify.org
```

---

## 1. Routing health first

Broken routing feels like a slow or dead VPN. Before tuning MTU or BBR:

```bash
sudo bash deploy/fix-vpn-routing.sh --role entry   # on entry
sudo bash deploy/fix-vpn-routing.sh --role exit    # on exit
sudo bash deploy/diagnose-vpn.sh --role entry
sudo bash deploy/test-connectivity.sh --role all
```

Common fixes are applied automatically by install and `tune-vpn-performance.sh`:

- Client subnet routed via `wg-clients` on entry
- Policy routing table 100 for twohop egress
- `rp_filter=0` on WireGuard interfaces
- Docker `DOCKER-USER` bypass on entry (if Docker is installed)

## 2. VPN mode: speed vs privacy

| Mode | Path | Speed | Egress IP |
|------|------|-------|-----------|
| **direct** | Device → entry → internet | Fastest | Entry server |
| **twohop** (default) | Device → entry → tunnel → exit → internet | Extra hop + CPU | Exit server |

### Assign modes

**Admin panel:** Clients → VPN mode dropdown when adding/editing a client.

**CLI (entry server):**

```bash
# Speed-sensitive user
sudo wg-client set-mode alice direct

# Privacy-focused user
sudo wg-client set-mode bob twohop

# Apply routing after bulk changes
sudo wg-client sync-vpn-modes
```

**Verify on client device:** `curl -4 https://api.ipify.org` — direct shows entry IP, twohop shows exit IP.

## 3. Server placement and sizing

| Choice | Recommendation |
|--------|----------------|
| Entry location | Close to **users** (low UDP latency on port 51820) |
| Exit location | Good peering / close to **target content**, or same region as entry |
| Collocation | Entry + exit in same datacenter reduces tunnel RTT while keeping separate IPs |
| Entry CPU | Matters for **twohop** (double crypto on entry) |
| Exit bandwidth | All twohop users share exit egress — size for aggregate throughput |

Upgrade VPS tier if `wg show wg-clients transfer` grows but user speeds plateau.

## 4. MTU settings

Client configs are generated by `wg-client`. Defaults (in `/etc/wireguard/entry-server.env`):

| Variable | Default | Use |
|----------|---------|-----|
| `WG_CLIENT_MTU` | 1280 | Fallback MTU |
| `WG_CLIENT_MTU_DIRECT` | 1420 | Direct mode (single hop) |
| `WG_CLIENT_MTU_TWOHOP` | 1280 | Twohop (double encapsulation) |

### Change defaults

Edit `/etc/wireguard/entry-server.env`, then create **new** clients or renew existing ones:

```bash
sudo wg-client renew alice --days 30
```

Or override per client:

```bash
sudo wg-client add bob --vpn-mode direct --mtu 1420
```

**TCP MSS clamp** (enabled by `tune-vpn-performance.sh`) helps when MTU is tuned upward on twohop paths.

## 5. OS performance tuning

Enabled by default on install (`WG_ENABLE_BBR=1`, `WG_ENABLE_MSS_CLAMP=1`).

| Setting | File / effect |
|---------|----------------|
| TCP BBR | `/etc/sysctl.d/99-wg-performance.conf` |
| UDP buffers | Same file (`rmem_max`, `wmem_max`) |
| MSS clamp | `iptables -t mangle … TCPMSS --clamp-mss-to-pmtu` |

### Disable (if needed)

```bash
WG_ENABLE_BBR=0 WG_ENABLE_MSS_CLAMP=0 sudo bash deploy/tune-vpn-performance.sh
```

Or set in `entry-server.env` / `exit-server.env` and re-run tune script.

## 6. Measure before and after

**On connected client (not the VPS):**

```bash
ping -c 20 ENTRY_PUBLIC_IP
curl -4 https://api.ipify.org
# Browser: fast.com or speedtest.net
```

**On entry server:**

```bash
sudo wg show wg-clients transfer
sudo wg show wg-tunnel transfer
sudo bash deploy/diagnose-vpn.sh --role entry
```

Compare **direct vs twohop** for the same user at the same time of day.

---

## 7. Larger architecture changes

Only if the steps above are insufficient:

| Option | Effect |
|--------|--------|
| All users on **direct** | Removes tunnel hop; exit unused for egress |
| **Single VPS** | One WireGuard hop; simplest; no separate exit IP |
| **Multi-exit** by region | Custom routing; not built into panels today |

The built-in compromise is **per-client `direct` vs `twohop`**.
